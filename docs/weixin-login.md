# 切换到绑定微信账号

## 入口和账号归属

当前登录用户的 `/userInfo` 包含 `provider=weixin` 时，在头像左侧展示微信入口。通过该入口登录后持久化 `loginMethod=weixin`，刷新页面后不再展示；短信登录恢复为 `phone`。

沿用当前助手用户 ID、手机号、会员、订单及邀请码，仅更新上游百词斩 token、昵称和绑定资料。代理端按助手用户共享上游 token，因此其他已登录会话的后续请求也会使用更新后的凭据。

## 接口

`POST /login/weixin`，携带现有 `access_token` 请求头，无请求体，要求普通用户登录权限。成功返回现有 `Response<String>`，`code=200`、`data=助手 JWT`；业务失败返回 `code=500`、`message=登录微信账号失败`。

代理端用当前登录态检查微信绑定，调用 `get_third_party_user_info`，再调用 `third_party_login`。身份参数全部由代理端获取，浏览器不提交微信 ID 或令牌。

| ThirdPartyLoginRequest 字段 | 来源 |
| --- | --- |
| provider | weixin |
| uid | uid，缺失时取 unionid |
| nickname | nickname |
| image_url、gender | 同名字段，缺失为空字符串 |
| api_token | atoken，有值才传 |
| token_expire | expires_at，有值才传 |
| openid、unionid | 同名字段，有值才传 |
| device | 现有设备标识逻辑 |

不传 `code` 或 `asecret`。详情为空、provider 不匹配、缺少昵称或所有身份标识时拒绝切换。

获取新上游 token 和用户资料后，复用公共登录收尾流程。微信更新处于数据库事务中，失败回滚并恢复请求上下文；提交后失效本地用户缓存。

## 学习数据与失败处理

切换期间锁定操作并暂停新增业务请求，等待既有请求和学习同步结束。逐书尝试上传剩余队列一次，同步失败也继续登录。只有获得新 JWT 后才清理旧认证、学习记录、未上传队列、草稿、单词本及统计，并安装新登录态、重新加载首页。

微信登录失败保留原账号和剩余待上传记录。同步失败但切换成功时，提示原账号未同步记录已清理。会话版本检查阻止旧请求及旧学习页面回调回写新账号缓存。

## 部署和联调

- 先发布代理端，再发布 Web；旧短信登录接口和 `/userInfo` 返回结构保持兼容。
- 仓库 Thrift 定义已包含两个微信方法，但本地生成客户端尚未更新。完整构建环境需使用现有 `thriftGen` 流程重新生成客户端及依赖 jar；本次未执行任何后端编译、构建或测试。
- 尚未调用真实上游微信接口验证可用性。联调需确认详情可用于登录、会员归属不变、切换后学习数据重新加载，以及业务失败时旧账号仍可用。
- 不包含微信扫码授权、手机号绑定和多浏览器会话独立凭据管理。
