# 学习同步

学习界面保留现有学习、复习和评分策略。同步记录以一题最终结果为单位，使用 IndexedDB 事务保存，不依赖页面退出时的网络请求。

## 本地存储与初始化

数据库 `baicizhan-study` 版本为 `1`，按持久化账号会话标识隔离，只接受当前格式。累计记录、未上传增量、冻结批次、租约、会话草稿和事件确认标识共同持久化。当前格式快照结构无效时重建该账号快照并重新拉取；数据库打开、读写失败会报错，不清空数据。

每次确认答题时，在同一事务中更新累计记录、待上传增量、去重标识及已提交检查点。界面只有在事务成功后才能前进；恢复已提交题目不会再次增加计数。会话结束后保留墓碑，迟到检查点不能恢复旧会话。

启动时定向删除旧学习记录、草稿和迁移标记，不读取原 `baicizhan-study-v3`。旧本地进度、历史未上传统计和旧草稿不恢复、不补传；登录态、设置、用户单词本及服务器进度保留。

首次使用必须成功获取远端学习列表，空列表也是成功。`lastPulledAt` 记录成功获取并落地的时间，`preparedBookId` 表示当前词书可开始学习；未知版本仍需对账，但不阻塞已有可用进度。首次拉取失败显示重试，不当作全部未学。已有当前格式记录时，上传或后台对账失败不阻塞继续学习。

词书目录和用户单词本独立加载。当前词书的学习分类不可用时仍展示全部单词，并提供局部重试；计划加载失败与服务器明确没有计划分别展示。草稿只恢复当前格式且日期有效的会话，其他草稿直接重新开始。

## 答题与计数

- 错选点击只设置本题错误标记。最终选对或耗尽机会时增加一次作答，曾错选则增加一次错误。
- 拼写保留当前纠错交互，以本轮最终结果结算；详情继续、重复提交和旧回调不增加计数。
- 每次展示与重试都有稳定的题目标识。有效耗时按题累计，页面隐藏或暂停期间停止计时。
- 复习选择和拼写分别记录次数，词级分数与轮次单独结算一次。
- 斩词是单次状态操作；取消斩词不增加作答次数。整组结束不再重复添加逐题统计。

## 上传与对账

待上传计数是未确认操作的增量；分数、能力分、标签和轮次取最新状态。50 个待同步 topic 触发自动上传，每批最多 800 个。完成一组、切书、切账号和手动同步会主动补传。

同一本书通过有期限的数据库租约排他上传。批次冻结后不再修改，新答题进入下一批；仅返回码 `0` 可以确认该批次。普通失败保留原批次内容，按 2、5、15、30、60、300 秒退避重试，之后最多每 300 秒一次。403 在当前账号会话内暂停自动请求，权限恢复后点击“立即同步”恢复尝试；401 继续按认证失效规则处理。

联网和回到前台只检查当前词书及有待传数据的词书，先查版本，不一律强制全量拉取。无待传时前台检查按账号、词书冷却 60 秒；网络恢复、完成整组、切书及手动同步不受该冷却限制。后台同步其他词书不获取 roadmap。租约心跳只访问本地 IndexedDB。

上传版本 `lastUploadedVersion` 与下行版本 `lastPulledVersion` 独立。上传前检查其他设备进度，上传成功后强制拉取。下行拉取前后版本一致且已知，记录成功落地后，才确认下行版本。未知或变化的版本继续保留 `needsFullPull`。

下行转换：`span_days === 0` 表示今日新学，`update_days` 对应距上次学习的天数，`created_at` 从秒转毫秒。创建时间不作为最后作答时间。跨天按本地自然日只归一化一次，未冻结待传状态随之更新，冻结批次保持原内容。

## Proxy 接口兼容

- `POST /updateDoneData` 保留 `resultCode / syncVersion`。成功版本是本次 RPC 使用的秒级时间戳，不再依赖成功后的元信息回读。
- `GET /studySyncMeta` 保留 `bookId / remoteSyncVer`，新增 `versionKnown`；缺失或无效版本不是已同步的证明。
- `GET /learnedWords` 保持原有接口。远端合并不清理本地待上传增量。

本地事件标识和批次租约防止本地重复结算、双标签并发确认；上游 RPC 没有已验证的幂等请求标识。请求已经被服务端接受但响应丢失时，重试仍可能重复影响服务端统计，本实现不承诺恰好一次投递。

## 验证

`npm test` 验证事务、旧存储隔离、初始化与就绪状态、草稿、答题、批次、版本和账号边界；`npm run build` 验证生产构建。真实写入验收使用专用测试账号或取得当前账号的明确授权；APP 双设备互通另行验收。请求过滤、内存缓存及请求次数见 [接口请求精简说明](request_reduction.md)。
